The Deal Ledger

Design for Gregg · 2026-10-14 · the technical version is the companion file for the coding assistant (QX-AUDIT-TRAIL-DESIGN.md, same folder)

What it is. One running record, per deal, of every change to any number the model uses: what changed, what it was before, who changed it, when, why, and where it came from (which document and page, which conversation, or typed by hand). Any figure on any screen or report can open its history. Every report is stamped with the position in the record it was printed from, so a number handed to a lender can be reproduced later exactly as shown.

Why it matters. Free tools and general assistants can run the same calculations. None of them can answer "where did this number come from, who changed it, and what was it last month" across everyone on the deal. That is the one sentence in the pitch that nothing else can say, and it is the sentence the Peoria walk-through found empty.

What is already there

Checked on the live database this afternoon. Three partial records exist and nothing joins them:

  • Changes Landscaper makes are logged (206 of them, with old and new value, the reason, and who confirmed). Good; it becomes part of the ledger.
  • Document extractions are logged as batches with a rollback. Good; same.
  • The budget has empty slots for "source" and "confidence" on every line; nothing fills them. That is the "no evidence recorded" message you saw.
  • Anything a person types into a screen is not recorded at all. Of 378 tables, 230 note when a row last changed, 21 note who, none keep the old value. The parcel you double-click, the budget grid, the assumptions forms, the loan screen: no trail.

What one entry looks like

Peoria, parcel 1.101, lot size. Newest first.

#48,214Oct 14 10:11 · Gregg · lot product 40×120 → 50×125 · reason: "undo, test only"
#48,213Oct 14 10:10 · Gregg · lot product 50×125 → 40×120 · typed in the parcel table
#41,002Sep 28 09:14 · Landscaper, confirmed by Gregg · lot product (blank) → 50×125 · from Parcels PDF, page 3 · confidence 0.97
#12,880Nov 19 2025 · imported before the ledger · parcel created · no earlier history

A derived figure (an IRR, a cash-flow cell) opens the same way, listing the stored numbers it was built from, each with its latest entry, and the formula that combined them. Where an engine cannot yet list its inputs, the sheet says so rather than showing a partial chain as if it were complete.

How it gets built

Seven slices, each run by you locally before it goes live. The first four are the demo-worthy unit: after them every number you type in front of a prospect has a chain, and the existing Peoria lines read "entered Nov 19 2025, before the ledger" instead of "no evidence".

  1. The record itself, with Landscaper's changes flowing into it.
  2. Every writable screen writes to it, with the old value captured. This is the one that touches the most code.
  3. Document extractions write to it; the budget's empty source slots fill from it.
  4. The ⓘ sheet on typed-in figures.
  5. Report stamps and named versions.
  6. The ⓘ sheet on calculated figures (IRR, cash flow). Hardest, because the app has six separate IRR calculators and they would each need to say what they used.
  7. Parties and working versions.

The case against doing it now. It is plumbing, and slice 2 touches every screen that saves anything, in an app where "simple" changes cascade. For the Kern conversation, a convincing version is the Evidence chip on the budget and the Activity feed, which are slices 1–3; the rest can follow prospect feedback. What would make me wrong: if prospects turn out not to care who changed what, and only want the numbers, this is three weeks spent on a feature nobody clicks. Kern's own words ("we need a strategy for using AI in decisions") say they will care, because it is the thing that makes the AI's number defensible.

What it is not. Not an undo button (though it makes one possible), not permissions between parties (that comes with slice 7), not a signature on a version (could sit on top later).

Decisions you own

One at a time; the first decides the size of the first build.

  1. 1Which screens record changes in the first build?
  2. 1aThe land lane only: parcels, budget, pricing, absorption, loans, assumptions.
  3. 1bEvery screen in the app that saves anything.
  1. 2Held until 1: what the existing numbers show. 2a "entered before the ledger, on date X" · 2b nothing until next touched.
  1. 3Held until slices 1–4 ship: how parties work (who can create one, whether a lender edits or only comments).
  1. 4Held: how long the detail is kept. 4a forever · 4b forever for pinned versions, two years for the rest.
